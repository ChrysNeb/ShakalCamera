# Шакал Камера

Самостоятельное нативное Android-приложение на Java 17. Камера через **CameraX с backend Camera2**, обработка фото через Bitmap/Canvas, видео через **Media3 Transformer / MediaCodec / OpenGL ES**. Не WebView. Не зависит от сайтов и работает без интернета. Разрешение INTERNET отсутствует в манифесте.

## Установка

Откройте `ShakalCamera-1.0.2.apk` на Android **8.0 или новее**, разрешите установку из выбранного источника, установите приложение. Это подписанная отладочным ключом сборка для прямой установки, не релиз для Google Play. APK универсальный: ARM64, ARMv7, x86 и x86_64.

При первом запуске разрешите камеру. Микрофон запрашивается отдельно при включении звука для видео. Без микрофона можно снимать немое видео. Доступ ко всей медиатеке не нужен: импорт через системный выбор файла. На Android 8–9 для записи результата в галерею запрашивается разрешение на память.

## Что умеет

- Фото и видео с передней / задней камеры, фонарик при наличии, зум 1×/2×, фокус касанием.
- Уровни 1–10 и отдельный 12/10. В видоискателе можно включать облегчённое фото-превью фильтра, аппаратный GPU-фильтр, адаптивно 30/20/15 кадров/с; запись видео обрабатывается после остановки.
- Импорт фото/видео, сравнение с оригиналом, «Ещё шакальнее».
- Сохранение в системную галерею (`Pictures/ShakalCamera`, `Movies/ShakalCamera`), отправка через меню Android.
- Фото до 2048 px по длинной стороне; видео до 60 секунд, импорт до 200 МБ. Длинные импортированные ролики обрезаются до первой минуты.
- Прогресс, примерное оставшееся время, отмена. Во время обработки приложение лучше держать открытым; экран не гаснет.
- EXIF-поворот и отражение фото учитываются. Оригиналы из галереи не меняются. Съёмка сначала попадает в приватный кэш, в общую галерею — только по кнопке «Сохранить».

## Алгоритмы и отличие от сайтов

`Levels.java` содержит таблицы из фото- и видео-сайтов. Фото: Paint/Nearest/Чистый → несколько JPEG-проходов → билинейный апскейл → усиление насыщенности, небольшой шарпен и шум на высоких уровнях → финальный JPEG. Paint использует двухшаговое растяжение/уменьшение с лимитом рабочей площади 4 млн пикселей. В 12/10: 50 → 100 px nearest, палитра 32 цвета, JPEG 10, nearest до исходного ограниченного размера; экспорт PNG.

Видео — **нативная адаптация**, не точная копия FFmpeg: два реальных поколения H.264, понижение пространственного разрешения / битрейта и неровный VFR, усиление цвета, 16-цветный 12/10, лёгкий гостинг на всех уровнях, имитация rolling shutter при движении. Низкое пространственное разрешение задаётся GL-сэмплированием: маленькие физические поверхности часто не поддерживаются аппаратными кодеками. После второго прохода длинная сторона 480 px.

Звук: моно-смешивание внутри сохранённого числа каналов, телефонная полоса, sample-hold, bitcrush, тремоло, детерминированные пропадания; выход AAC. **MPEG4 AVI, порча битстрима, настоящий датамош с потерей I-кадров, MP3-поколения и x264 zones из сайта здесь не используются.** Битрейты Android-кодек может округлить; для AAC нижняя запрошенная граница 24 кбит/с ради совместимости. Шлейфы — визуальная имитация движения старых пикселей, не повреждение файла.

Основной просмотр после обработки — JPEG/PNG или MP4 H.264 + AAC. Точные размеры и поддержка кодирования зависят от устройства; предусмотрен codec fallback и сообщение об ошибке для неподдерживаемых роликов.

## Сборка

Установите JDK 17 и Android SDK (platform 35, build-tools 34.0.0; Gradle при необходимости загрузит дополнительные компоненты). Откройте эту папку как самостоятельный проект Android Studio либо укажите путь к SDK в `local.properties`:

```properties
sdk.dir=C:/Android/Sdk
```

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

Linux/macOS: `sh ./gradlew assembleDebug testDebugUnitTest lintDebug`.

Результат: `app/build/outputs/apk/debug/app-debug.apk`. Зависимости закреплены в Gradle, wrapper включён. Для Google Play нужен собственный release-ключ: отладочный APK не предназначен для публикации в магазине.

## Проверки

- `LevelsTest`: таблицы, усиление параметров, размеры / чётность.
- `PhotoNativeTest`: настоящий нативный Bitmap/Canvas через Robolectric, все 11 уровней × 3 ресемплинга, отличающиеся / не чёрные результаты, повторные прогоны, воспроизводимость шума, исходники 4000×3000 и 4032×3024.
- На телефоне или поддерживаемом эмуляторе: `gradlew connectedDebugAndroidTest`. `PhotoEngineTest` повторяет фото-проверки на реальном Android; `VideoEngineTest` обрабатывает сгенерированный движущийся testsrc2+sine на всех 11 уровнях, проверяет AVC/AAC, размер, декодирование кадра. Тесты не снимают пользовательские фото и не открывают микрофон.
- APK проверяется `apksigner verify`, SDK/ABI — `aapt dump badging`.

На Windows ARM / Snapdragon X официальный Android Emulator не поддерживается. Сам APK собран, но реальная камера и MediaCodec должны быть проверены на Android-телефоне; результаты локальных проверок перечислены в `TESTING.md`. Архитектура компьютера для сборки и ABI телефона — разные вещи.

## Приватность

Никаких серверов, аналитики, аккаунтов, водяных знаков или сетевых разрешений. Временные файлы старше суток удаляются при следующем старте. Системная очистка кэша также удалит несохранённые результаты. Отправка начинается только после нажатия «Поделиться» и выбора приложения.

## Исходники

- `MainActivity.java` — камера, экран, разрешения, сохранение, отправка.
- `PhotoEngine.java` — фото-пайплайн.
- `VideoEngine.java`, `PixelEffect.java`, `ShakalAudioProcessor.java` — потоковое видео и звук.
- `Levels.java` — таблицы параметров.

Зависимости AndroidX / Media3 / Guava — Apache-2.0 (их уведомления о лицензиях доступны в соответствующих Maven-артефактах).

## Неровное видео в 1.0.1

OldCameraEffect читает уменьшенную копию 32×24; FrameMotion оценивает яркость, разницу и движение по полосам. CameraCadence определяет реальные пропуски по PTS: до 20 новых кадров/с, провалы примерно до 10, замирания 430–570 мс. Основное расписание зависит от seed, дополнительные провалы — от сцены. В 12/10 сохранён более редкий базовый темп 8/6 кадров/с.

Пропущенные кадры не отправляются кодеру. Временные метки сохранённых кадров не сжимаются, поэтому пауза удерживает предыдущий кадр, а аудио не ускоряется. Гостинг лёгкий, история очищается при склейке; rolling shutter — программная деформация по оценке движения, не управление считыванием сенсора.

## GPU-превью в 1.0.2

GpuPreview реализует CameraX SurfaceProcessor только для PREVIEW. Камера передаёт кадр в SurfaceTexture / external OES, шейдер рисует в SurfaceOutput. Преобразования CameraX сохраняют поворот и отражение. В живом пути нет getBitmap, JPEG или CPU-чтения пикселей. PreviewView использует PERFORMANCE / SurfaceView, запрашивается 640×480 с аппаратным fallback размеров.

PreviewBudget удерживает цель до 30 кадров/с, снижает до 20/15 при длительном медленном рендеринге и восстанавливает темп с гистерезисом. Старые события кадров объединяются; GL-текстуры, матрицы и буферы переиспользуются. Превью — лёгкая визуальная аппроксимация. Полная обработка сохранённого кадра и VFR экспортируемого ролика не менялись.
